代码目录概览：核心音视频通话引擎
这个目录是一个 进程分离的 WebRTC 音视频通话客户端核心。它的设计思路是：WebRTC 引擎运行在一个 daemon 进程中，Qt GUI 运行在另一个进程中，两者通过 Unix Socket (JSON IPC) + 共享内存 (视频/音频帧) 通信。

执行流程：按时间线阅读
阶段 1：进程启动与初始化
阅读入口：[main.cc:24-56]


main()
 ├─ ParseCommandLine
 ├─ CreateEnvironment (field trials)
 ├─ 设置 WebRTC 主线程 (PhysicalSocketServer + Thread)
 ├─ InitializeSSL
 ├─ 配置日志 (FileRotatingLogSink)
 ├─ 创建 WebRTCEngine 实例
 └─ engine.Init()
WebRTCEngine::Init() (webrtc_engine.cc:503-518) 做了最关键的事——创建三条 WebRTC 线程：

线程	创建方式	职责
signaling_thread_	CreateWithSocketServer()	PeerConnection 所有 API 调用
worker_thread_	Create()	编解码、ADM 操作
network_thread_	CreateWithSocketServer()	网络 IO
这是 WebRTC 的三线程模型。signaling_thread 带 socket server 因为它还需要跑信令客户端。

阶段 2：模式分支
阅读入口：[main.cc:58-76]


if (standalone)
    CliRunner 接管 → 交互式命令行
else
    UnixSocketServer 接管 → daemon 模式，等待 Qt 进程连接
Standalone 模式：CliRunner::Run() (cli_runner.cc:23-54) 注册 event callback 将 JSON 事件打印到 stdout，然后进入 InputLoop 等待用户输入。

Daemon 模式：UnixSocketServer::Start() (unix_socket_server.cc:29-31) 启动一个 epoll IO 线程，监听 Unix domain socket，接收 JSON 命令。

阶段 3：连接信令服务器
阅读入口：webrtc_engine.cc:562-568 → peer_connection_client.cc:97-138


ConnectToServer(server, port)
  → PeerConnectionClient::Connect()
    → DNS 解析 (AsyncDnsResolver)
    → DoConnect()
      → 创建 control_socket_ + hanging_get_ (两个 TCP socket)
      → GET /sign_in?<name> HTTP/1.0
      → 状态: SIGNING_IN
关键设计：PeerConnectionClient 用了两个 TCP 长连接：

control_socket_：发送命令 (sign_out, message, hangup)
hanging_get_：服务器推送事件 (peer 上下线, 消息转发)，本质是 HTTP long-polling
阅读信令流程的核心回调链：


OnRead (control_socket_ 收到 HTTP 响应)
  → ParseServerResponse → 提取 Pragma header 中的 peer_id
  → 如果 SIGNING_IN: 解析已有 peer 列表 → OnSignedIn()
  → 启动 hanging_get_ 连接: GET /wait?peer_id=X

OnHangingGetRead (收到服务器推送)
  → 解析通知类型:
    ├─ 给自己: peer 上下线通知 → OnPeerConnected / OnPeerDisconnected
    └─ 给别人的消息: 转发给 OnMessageFromPeer

6 个关键设计要点
1. 线程模型
代码严格遵守 WebRTC 三线程模型。所有 peer_connection_->Xxx() 调用都发生在 signaling thread 上。UnixSocketServer 通过 engine_->signaling_thread()->PostTask(...) 将外部命令投递到 signaling thread。

2. 引用计数
全部使用 webrtc::scoped_refptr 管理 WebRTC 对象生命周期。CreateSessionDescriptionObserver 通过 make_ref_counted 创建 DummySetSessionDescriptionObserver。

3. 信令协议
信令服务器交互使用 HTTP/1.0 over TCP raw socket，不走标准 HTTP 库。两个长连接：control_socket (主动请求) + hanging_get (服务器推送 / long polling)。

4. 进程间媒体传输
媒体帧不经过网络序列化，而是通过 System V 共享内存环形缓冲区 在进程间零拷贝传递：

视频：shm_video_buf — 8 帧环形缓冲，I420 格式
音频输入 (mic)：shm_audio_cap — Qt 进程写入，WebRTC 引擎读出
音频输出 (speaker)：shm_audio_playout — WebRTC 引擎写入，Qt 进程读出
5. 视频源灵活性
CapturerTrackSource 继承 VideoTrackSource，支持热切换：SwapCapturer() 可以在通话中途切换摄像头而不重建 PeerConnection。

6. DataChannel 协商
DataChannel 使用 negotiated=true, id=0，这意味着它是带内协商的，不需要额外的 SDP 交换。
